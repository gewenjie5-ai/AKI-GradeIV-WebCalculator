# Postoperative AKI Prediction Calculator for Grade IV Abdominal Surgery

## Purpose

This repository provides version 1.0 of a standalone browser-based implementation of the frozen final shrinkage-adjusted prediction equation developed for postoperative acute kidney injury (AKI) after Grade IV abdominal surgery.

The calculator is provided for **research and independent evaluation only**.

## Model scope

- **Target population:** patients undergoing Grade IV abdominal surgery
- **Prediction time point:** completion of surgery
- **Outcome:** postoperative AKI within 7 days
- **Model:** final 11-predictor global-shrinkage-adjusted logistic prediction model
- **Validation status:** bootstrap internal validation in the development cohort; independent external validation has not yet been performed

The calculator does not define risk strata, treatment thresholds, intervention thresholds, or treatment recommendations.

## Frozen implementation

The public calculator file is:

`AKI_GradeIV_WebCalculator_frozen.html`

It reproduces the final shrinkage-adjusted prediction equation reported in Table 2 of the accompanying manuscript. Continuous predictors are entered in their original model units, and binary predictors use the frozen No = 0 / Yes = 1 coding.

For convenience, the webpage derives prognostic nutritional index (PNI) automatically from preoperative serum albumin and peripheral blood lymphocyte count:

`PNI = serum albumin (g/L) + 5 × peripheral blood lymphocyte count (×10^9/L)`

Albumin and lymphocyte count are source inputs used only to derive PNI and are not additional predictors in the frozen 11-predictor model. The webpage uses the unrounded derived PNI value in the prediction equation.

## Use

Open `AKI_GradeIV_WebCalculator_frozen.html` in a modern web browser. The calculator is a standalone HTML file and performs calculations locally in the browser.

No risk category, recommended cutoff, treatment recommendation, or clinical intervention threshold is generated by the webpage.

## Quality control

The frozen implementation underwent software-level checks of coefficient use, predictor coding and units, input handling, PNI derivation, reproduction of the prespecified illustrative calculation, offline operation, responsive layout, and use-boundary wording. These checks did not involve model refitting, recalibration, predictor reselection, threshold optimization, or re-estimation of model performance.

## Validation and interpretation boundary

The underlying model underwent bootstrap internal validation in the development cohort. The web implementation does not constitute independent external validation, category-specific validation, clinical-impact evaluation, or evidence that use of the calculator improves clinical decisions or patient outcomes.
